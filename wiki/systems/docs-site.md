# Docs Site

The public documentation site at [badge.temporal.io](https://badge.temporal.io) lives at `docs/` and is deliberately minimal: plain HTML and CSS, no client-side JavaScript, no build step, and no package manager. Vercel serves the directory directly per the root `vercel.json`, and `docs-build.yml` runs Lighthouse against the home page before docs changes merge — the zero-JS, zero-build-step choice is what keeps that Lighthouse gate meaningful and keeps the site working when opened straight from disk (`docs/index.html`) with no local server.

The page set is fixed and topic-scoped: `index.html`, `basics.html` (first-use overview), `get-started.html` (flashing + JumperIDE + first app), `developer-guide.html` (MicroPython development), `api-reference.html` (badge MicroPython API summary), `apps.html` (app structure and filesystem), `hardware.html` (an overview of, and pointer into, the [hardware package](../components/hardware-package.md)), and `hacks.html` (advanced/IR topics).

## Stylesheet load order is load-bearing

Every page links `base.css` first, then whatever page-level sheets it needs, then `css/responsive.css` last. This isn't just convention — `base.css` and the page-level sheets redeclare some of the same selectors at the same specificity, so whichever sheet loads last wins, and all breakpoint/media-query rules live in `responsive.css` specifically because a `@media` block carries no extra CSS specificity: a media rule declared in an earlier sheet is silently overridden by a later sheet touching the same selector, even outside that breakpoint. Adding a new stylesheet to a page means keeping `responsive.css` last, not just appending it. Shared values (`--mono` type stack, `--panel-solid`, color tokens) are custom properties on `:root` in `base.css`.

## Screenshots and content

`docs/assets/screenshots/` holds captured badge OLED screenshots, produced with `firmware/scripts/capture_oled_fb.py` (see the [OLED screenshot runbook](../runbooks/capturing-oled-screenshots.md)) rather than hand-drawn mockups, so the docs site's visuals track the real on-device UI. `docs/assets/photos/` holds public event photography used across repo docs, including the README; per `docs/assets/photos/README.md` and [third-party licensing](../concepts/third-party-licensing.md), those photos aren't source code and aren't covered by the repo's MIT license.

## A drifting, undocumented third copy of the app docs

`docs/README.md`'s file list for this directory doesn't mention it, but `docs/markdown/badge-api-reference.md` and `docs/markdown/badge-developer-guide.md` exist alongside `api-reference.html`/`developer-guide.html` and are a **third** copy of the MicroPython app-authoring reference, distinct from both the rendered HTML pages and the badge-embedded `firmware/initial_filesystem/docs/API_REFERENCE.md`/`MicroPythonDeveloperGuide.md` (which the badge itself carries on FATFS — see [badge apps](../components/badge-apps.md)). As of this repo's HEAD, `docs/markdown/` is measurably ahead of the on-device copy: it documents `oled_screenshot()`, persistent matrix apps, IR "playground" modes, and a firmware-updates/Community-Apps section that the badge-embedded docs don't have yet. It isn't clear from any README whether `docs/markdown/` is a staging draft meant to be synced into the HTML pages and the on-device docs, or an independently-maintained reference that's simply allowed to lead — this is worth asking about before treating either copy as fully authoritative for a specific API's current shape.

## What the live site actually shows (verified 2026-09-16)

Fetching the deployed site directly confirms the page set matches this page's list exactly — the nav bar links `get-started.html`, `basics.html`, `developer-guide.html`, `hardware.html`, `api-reference.html`, `apps.html`, and `hacks.html`, plus external links to GitHub, `temporal.io`, and JumperIDE (`ide.jumperless.org`). This gives a third data point beyond the two already noted above (the badge-embedded docs and `docs/markdown/`): the live `api-reference.html` documents OLED/UI/helper-module/button-joystick/LED-matrix/matrix-app-host/IMU/haptics/IR/HTTP-serial/identity/KV/script-control/mouse-overlay/native-surface sections, but — consistent with [BLE proximity](../components/ble-proximity.md) being excluded from the public build — mentions no BLE, OTA, or asset-registry APIs at all, and shows neither `oled_screenshot()` nor persistent matrix apps as a documented feature. That makes the live site the *most conservative* of the three doc copies: less far ahead than `docs/markdown/`'s draft content, but also clean of the stale `-e echo` build commands found in the badge-embedded and `docs/markdown` copies — `developer-guide.html`'s own Ignition and PlatformIO examples correctly use `pio run -e replay2026`. `hacks.html` documents `gc.collect()`/heap discipline, the `oled_show()` framebuffer-flush requirement, `led_override_begin()`/`led_override_end()` wrapping, `button_pressed()` single-read-per-loop, the four-button-held force-exit, IR's `ir_start()` exclusivity and ~50 ms poll budget, and required app-exit cleanup (LEDs, haptics, tones, IR, mouse overlay) — none of which contradicts anything already documented elsewhere in this wiki.
