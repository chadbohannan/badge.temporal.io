# UI Rendering Conventions

Three conventions in `firmware/src/ui/` keep the badge's many screens visually and behaviorally consistent instead of every screen hand-rolling text, hints, and cursor logic against the raw `oled` driver wrapper.

## Never spell out a button letter

`ButtonGlyphs.h` opens with an explicit project rule: face-button labels (Y/B/A/X) are not stable strings a screen can safely print, because `kSwapConfirmCancel` can swap which physical button means confirm vs. cancel, and [nametag-flip orientation](gui-screen-stack.md) rotates which physical button reads as which direction. Any hint or status text has to route through `drawInlineHint(...)`/`drawActionFooter`/`drawFooterActions`/`drawFooterHint`, which substitute the correct glyph for tokens like `X`, `A`, `B`, `Y`, `^`, `v`, `Confirm`, `Cancel` at render time rather than a screen ever calling `oled::drawStr` with a literal button letter baked in. `OLEDLayout.h` — the shared header/footer/content-region geometry (`kFooterTopY`, `kHeaderRuleY`, `kContentTopY`, etc.) — is the layout half of the same consistency goal: screens position content relative to these named constants instead of hardcoding pixel offsets that would need updating in dozens of places if the chrome ever changed.

## The mouse overlay is native now, Python was first

`MouseOverlay` (`ui/MouseOverlay.{h,cpp}`) is a relative/absolute-mode joystick-driven cursor rendered by XOR-compositing (`setDrawColor(2)`) onto the OLED buffer — drawing it twice cancels out, which doubles as its own restore-after-flush mechanism with no separate erase pass needed. It originally lived only inside the MicroPython bridge (`badge_mp_api/mp_api_mouse.cpp`) as a Python-app-only feature; it was later promoted into `ui/` so native C++ screens could drive the same cursor, with the Python-facing `mouse_overlay`/`mouse_x`/`mouse_y` API left unchanged and now just delegating to the native module. All of its state is single-translation-unit and Core-1-only (GUI tick and display-flush hooks), so it needs no locking — a pattern worth matching for any future native module that's Core-1-exclusive by construction rather than by convention.

## One size ladder, ten font families

`FontCatalog.cpp` exposes fonts to the rest of the firmware two ways: `kFontGrid[family][size]` is a 10×10 lookup (family 0-9 × a universal 4px-to-XL size scale, `kSizeLabels`) used by anything that lets a user cycle sizes independently of the chosen family — like the nametag's size-shrink-on-overflow logic — while a separate flat `kReplayFonts[]` array (with human-readable names like `"Profont 17"`) backs `setFont(name)` calls from both native code and the MicroPython bridge. The grid isn't uniform underneath: several families top out early in the native U8G2 catalog and reuse their largest available font for the remaining "big" slots (Fixed repeats `10x20` for both XL slots; NCen repeats `18` for its last two), and the Terminus family's comment calls out that its `_tr` variant simply doesn't exist at 22px in u8g2 — only the numbers-only `_tn` does — so Terminus jumps straight from 17px to 30px, meaning a caller cycling through "every size" on Terminus sees a bigger jump than on other families at that step.

## `QRCodePlate`: one draw call for every QR code on the badge

`QRCodePlate::draw()` (`ui/QRCodePlate.cpp`) is the single shared routine for rendering a QR code's white rounded-corner backing plate and centering the QR bitmap inside it — every screen that shows a QR code (pairing, asset install links, contact sharing) calls this instead of hand-drawing a box and XBM blit, which keeps the "quiet zone" margin and corner radius (`kPlateCornerRadius = 3`) visually consistent across all of them. It's a deliberately tiny, stateless helper: 33 lines, no member state, callers own bitmap generation and only hand it `(bits, width, height, x, y, plateSize)` plus an optional vertical divider line for side-by-side layouts.

## The on-screen keyboard tracks a byte cursor, not a character cursor

`TextInputScreen` supports two independent input styles — Grid mode (joystick moves a cell selector over a QWERTY layout) and Mouse mode (the joystick drives an absolute cursor, and moving it above the keyboard row switches to text-cursor insertion) — plus a six-page emoji picker and a three-state Shift (`None`/`OneShot`/`Locked`, with tap-vs-double-tap-vs-hold distinguishing them). `cursorPos_` is explicitly a **byte** offset into the buffer, not a glyph index, because emoji commit multi-byte UTF-8 sequences (`commitBytes`) alongside single-byte ASCII (`commitChar`); `backspace()` and the left/right cursor-move helpers walk backward over UTF-8 continuation bytes (`10xxxxxx`) rather than assuming one byte per visible character, so deleting or navigating past an emoji removes or skips the whole multi-byte glyph in one step instead of corrupting it into orphaned continuation bytes. `mode_` is deliberately sticky across separate keyboard invocations within the same boot (toggling into Mouse mode once means every subsequent text entry that boot opens in Mouse mode) — a small persistence choice that isn't NVS-backed and doesn't survive a reboot, unlike the settings covered on the [storage model](storage-model.md) page.
