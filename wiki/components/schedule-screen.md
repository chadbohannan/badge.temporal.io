# Schedule Screen

`firmware/src/screens/ScheduleScreen.cpp` and its data layer `ScheduleData.cpp` are the conference-schedule feature — pure C++ in the native [screen stack](gui-screen-stack.md), not a MicroPython app. `ScheduleScreen` renders two synced views (a date-tab picker and a paginated event list, two concurrent events per row when a slot has parallel sessions) and pushes `ScheduleDetailModalScreen` — a [`ModalScreen`](gui-screen-stack.md) subclass — for a selected event's description, time range, and an optional "locate" chip that hands off to `MapScreens` via `mapSetTargetFloor`/`mapSetTargetSection` when the event's room resolves on the venue map.

## Data comes from cache-or-embedded, never live over the network

Despite `ScheduleScreen::onEnter`'s comment describing a "cache-first, kick off the network fetch" flow, `ScheduleData.cpp` contains no network fetch at all: `sched_start_refresh()` → `sched_ensure_cache_loaded()` only tries `Filesystem::readFileAlloc()` against two hardcoded FATFS paths (`/schedule_full_v2.msgpack`, `/schedule_your_v2.msgpack`), and falls back to the embedded `DataCache::schedule()` bundle baked into the firmware at build time (see [Data Bundle](data-bundle.md)) when the cache file is missing. Nothing else in this public repo ever writes those two cache paths — no HTTP client, no `AssetRegistry` entry, no script — so on a badge built from this tree alone, the schedule is always the static bundle compiled in at flash time. This is consistent with `DataCache`'s own documented behavior (its `defaultDownloader()` is a stub that always reports unavailable, "no longer reach[ing] out to the Replay API" per its own comment); the live cache path likely exists for a private event-ops pipeline that pushes fresher msgpack onto FATFS out of band, outside this repo's scope (see the [public/private scope boundary](../concepts/public-repo-scope-boundary.md)).

`s_refreshInProgress`, the flag that would show a "SYNC" status token in the header and gate `sched_is_loading()`, is declared but never set `true` anywhere in the file — another sign the network-refresh half of this design was never wired up in the public tree, only the cache/embedded-fallback half.

## "MINE" personal schedule mode is a dead toggle

`ScheduleData.cpp` defines a full `ScheduleMode::kPersonal`/`kFull` split — `sched_mode_label()` would show "MINE" instead of "ALL", `sched_days()` would serve an empty per-user schedule instead of the full one — but `s_mode` is initialized to `kFull` and nothing in the file ever assigns it `kPersonal`. `sched_toggle_mode()` (bound to the Y button in `ScheduleScreen::handleInput`) unconditionally calls `sched_use_full_mode()` and always `return`s `false`, so the `if (sched_toggle_mode()) { ... }` branch in `handleInput` — which would reset the view and haptic-pulse on a successful toggle — is itself unreachable. Pressing Y on the schedule screen is currently a complete no-op. `sched_needs_pairing()` and `sched_show_custom_schedule_prompt()` are likewise hardcoded to `false` with no caller ever making them otherwise. This reads as the same "retired feature, live but inert" pattern as `Screen::access()`'s [`ScreenAccess` routing](gui-screen-stack.md) — a personal/starred-talks schedule feature (plausibly tied to the same paired-account system pairing removal retired) left compiled in rather than deleted.

## Rendering: double-buffered runtime store, paginated rows, room-filter mode

`ScheduleData` keeps two `RuntimeStore` instances (`s_runtime[2]`, PSRAM-allocated via `BadgeMemory::allocPreferPsram`) and an `s_activeRuntime` index rather than parsing new data directly over the array the screen is currently reading — `parseAndApply()` always fills the *inactive* buffer and only flips `s_activeRuntime` once parsing succeeds, so a corrupt or partial cache/bundle read never leaves the screen showing a torn schedule mid-parse.

`ScheduleScreen`'s event list paginates two concurrent events per row (`rowOfEvent`/`pairedCol1`/`nextRow`/`prevRow`) when a time slot has parallel sessions, falling back to a single wide "solo" cell when it doesn't; the selection frame grows vertically to span a multi-row-long event (e.g. a workshop or Birds-of-a-Feather block) rather than clipping to one row, with the event's end time redrawn on the frame's last row. A separate hidden mode, entered only via the venue map's "confirm" action on a room section (not directly navigable from the schedule's own UI), replaces the whole view with `drawFilteredView()` — a flat, single-room event list with its own cursor and scroll state (`filterCursor_`/`filterScroll_`), used for "what's playing in this room" lookups from the map rather than the schedule.
