# Doom Port (removed)

**Fully removed as of 2026-09-17** (customizing_badgy branch). The badge briefly ran a DoomGeneric-based Doom port as a hard-takeover "app mode" gated behind `-DBADGE_HAS_DOOM`, using the shareware `doom1.wad`. The badge maintainer judged it unplayable — the OLED's 1bpp SSD1306 output can't render the gradients DoomGeneric's dithered downsample needs, so gameplay read as noise — and had it pulled in two steps:

1. **2026-09-16**: menu-level swap. The "DOOM" tile in `GUI.cpp`'s main menu was replaced with a "HELGRIND" placeholder (`HelgrindScreen`, a static "game coming soon" message, `kScreenHelgrind`) while the Doom implementation stayed compiled-but-unreachable.
2. **2026-09-17**: full removal. `firmware/src/doom/` (DoomScreen, doom_app, doom_hal, doom_input, doom_render, doom_resources, doom_sound, doom_hud_matrix) and the entire vendored `firmware/lib/doomgeneric/` engine were deleted; `-DBADGE_HAS_DOOM`, `-Ilib/doomgeneric/src`, `-DDOOMGENERIC_RESX/RESY`, and the `doomgeneric` `build_src_filter` entry came out of `firmware/platformio.ini`; the `doom1-shareware` entry was dropped from `registry/community_apps.json` / `RegistryDownloadables.h`; `firmware/initial_filesystem/doom1.wad`, `licenses/DOOM1-WAD.txt`, `licenses/GPL-2.0.txt`, and `firmware/codeDocs/DOOM.md` were deleted; and Doom mentions were scrubbed from `THIRD_PARTY_NOTICES.md`, the public docs site (`docs/basics.html`, `docs/markdown/badge-developer-guide.md`), and various build/release scripts. Two non-cosmetic fixes fell out of that pass: `.github/workflows/release-firmware.yml` had a `test -f doom1.wad` gate that would have hard-failed every release build once the WAD was gone, and `ignition/flash_worker/activities.py`'s `_doom_wad_present()` early-return would have silently skipped filesystem rebuilds unconditionally once the WAD no longer existed locally. The flash image shrank from 72.3% to 64.6% of the `replay2026` partition as a result. See [known cruft](../syntheses/known-cruft-and-dead-code.md) for the retirement history.

**Left deliberately untouched**: `firmware/platformio.ini`'s `board_build.partitions = partitions_replay_16MB_doom.csv`, the CSV itself, and `firmware/src/ota/BadgeOTA.cpp/.h`'s `_doom`/`_ver2` partition-layout naming and migration logic (`kNvsLastLayout`). `_doom` is a historical partition-layout name baked into already-flashed badges' NVS state — unrelated to whether the game code exists, and a separate, higher-risk change if ever revisited.

Nothing else in this codebase references the removed engine; a full case-insensitive repo grep (excluding `wiki/` and `.git/`) confirms the only remaining `doom` hits are the partition-layout name above.

The "HELGRIND" tile from step 1 is still a placeholder — the game that actually shipped into that menu slot's neighbor is [Vectortank](vectortank.md), a native C++ Battlezone-style demo added as a separate "VECTOR" tile rather than a replacement for Helgrind.
