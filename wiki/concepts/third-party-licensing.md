# Third-Party Licensing Inside an MIT Repo

The repository is MIT-licensed by default (`LICENSE`), but `THIRD_PARTY_NOTICES.md` carves out several pieces that aren't: firmware binaries that include the [Doom port](../components/doom.md) bundle GPL-2.0-or-later DoomGeneric engine source, which means a Doom-enabled firmware binary is not MIT-only and must be redistributed under GPL-compatible terms with corresponding source available (`licenses/GPL-2.0.txt`). The `doom1.wad` shareware data itself is separately non-open-source game data owned by id Software — freely redistributable but not covered by this repo's license at all (`licenses/DOOM1-WAD.txt`), which is why the firmware credits id Software before launching Doom.

Two [Community Apps](../components/community-apps-registry.md) — Durable Snake and Starfield Nametag, both by Alexandre Roman, imported from his separate `temporal-replay-2026-badge-apps` repository — carry Apache License 2.0 terms (`licenses/Apache-2.0.txt`) rather than this repo's MIT default, so their Apache notices need preserving on redistribution. A third Community App, Tardigotchi by aask42, and the public event photo `docs/assets/photos/replay-badge-table.jpg`, are also called out individually: the photo is documentation content, not source, and isn't covered by the MIT license either.

The practical effect for anyone building or redistributing a factory image: **whether a given build is MIT-only depends on whether it bundles Doom**, and `THIRD_PARTY_NOTICES.md` says outright that it "should be expanded as the firmware import is completed and the exact vendored dependency set is finalized" — MicroPython, Arduino/ESP32/PlatformIO libraries, QR utilities, U8g2, ArduinoJson, and Adafruit/SparkFun libraries are named as known-but-not-yet-fully-enumerated dependencies with their own upstream license notices to preserve.
